# eLama vs PromoPult — референсы для DirectPilot Beta

Дата: 2026-06-05

## Краткий вывод

**eLama стоит добавить в референсы DirectPilot Beta.** Но не как продукт, который нужно копировать целиком, а как пример прагматичного набора инструментов вокруг рекламного кабинета: статистика, мониторинг, автоправила, бид-менеджер, UTM, рекомендации, поддержка.

**PromoPult** полезен как референс позиционирования “автопилот продвижения”.  
**eLama** полезнее для MVP-функций: “операционный хаб для рекламы”.

Для DirectPilot Beta лучше взять из eLama:

1. диагностику кампаний;
2. explainable recommendations;
3. sandbox-автоправила;
4. UTM generator;
5. мониторинг и алерты;
6. симулятор бюджета/ставок.

Не стоит брать в MVP:

- единый кошелёк;
- постоплату;
- агентские вознаграждения;
- marketplace инструментов;
- 25+ рекламных систем;
- юридически сложную инфраструктуру оплаты/документов.

## Что такое eLama

eLama позиционируется как платформа с инструментами для интернет-рекламы:

- настройка первой кампании в Директе/VK/Telegram Ads/Авито;
- поддержка 24/7;
- оплата 25+ рекламных систем с одного счёта;
- постоплата;
- статистика;
- бид-менеджер;
- автоправила;
- UTM-разметка;
- мониторинг;
- минусатор;
- калькулятор ставки;
- лингвогенератор;
- маркировка рекламы;
- автоматические рекомендации.

Для агентств eLama дополнительно продвигает вознаграждения, постоплату, маркировку, единый кабинет и перенос аккаунтов.

## Что взять из eLama для DirectPilot Beta

### 1. Campaign Audit

Идея: сервис находит ошибки и слабые места в кампаниях.

Для DirectPilot Beta:

- mock-аудит кампаний;
- список проблем: нет UTM, нет минус-слов, высокий CPC, низкий CTR, нет целей Метрики;
- severity: low / medium / high;
- reason: почему это проблема;
- suggested_action: что сделать;
- expected_effect: ожидаемый эффект.

API-кандидаты:

- `GET /audit/campaigns`
- `GET /recommendations`

### 2. Explainable Recommendations

Идея: не “магический ИИ”, а понятные рекомендации.

Для DirectPilot Beta:

- причина;
- риск;
- confidence;
- какие данные использованы;
- кнопки approve/reject;
- dry-run перед применением.

### 3. Autopolicies / Rules Sandbox

Идея eLama: автоправила для Яндекс Директа.

Для DirectPilot Beta в MVP:

- rule templates;
- sandbox simulation;
- журнал срабатываний;
- без реальных write-действий до одобрения API.

Первые правила:

- расход есть, конверсий нет → предложить остановить ключ;
- CTR ниже порога → предложить заменить объявление;
- CPC выше лимита → предложить снизить ставку;
- нет UTM → предложить исправить ссылку;
- нет цели Метрики → запретить auto-apply.

### 4. Bid/Budget Simulator

Не делать настоящий биддер в MVP. Вместо этого:

- симулятор изменения ставки;
- max CPC;
- daily/monthly budget;
- прогноз расхода;
- сценарии: осторожный / сбалансированный / агрессивный.

### 5. UTM Generator

Дешёвая и полезная функция для малого бизнеса.

Для MVP:

- `utm_source=yandex`
- `utm_medium=cpc`
- `utm_campaign={campaign_id}`
- `utm_content={ad_id}`
- `utm_term={keyword}`

API-кандидат:

- `POST /utm/generate`

### 6. Simple Monitoring

Для MVP:

- расход;
- клики;
- CTR;
- CPC;
- CPA, если есть Метрика;
- алерты: “расход идёт, заявок нет”, “CTR ниже нормы”, “кампания без цели”.

## Что не копировать из eLama

### Единый кошелёк / оплата 25+ систем

Не нужно в MVP:

- юридически сложно;
- требует биллинга и документооборота;
- не помогает получить первый working demo.

### Постоплата

Не нужно:

- кредитный риск;
- юридическая нагрузка;
- не связано с API-first MVP.

### Агентская партнёрская программа

Не нужно сейчас:

- DirectPilot Beta стартует как инструмент для себя/малого бизнеса;
- агентский реселл и вознаграждения — отдельная экономика.

### Marketplace инструментов

Не нужно:

- слишком широкий scope;
- много интеграций;
- размывает продукт.

### 25+ рекламных каналов

Не нужно:

- сначала Яндекс Директ;
- потом Метрика;
- другие каналы только после доказательства ценности.

## Нужно ли переписывать текущие планы

**Полностью переписывать не нужно.** Текущий план верный: API-first, mock/sandbox-first, approval, audit, read-only до одобрения.

Но стоит добавить в roadmap новый блок, вдохновлённый eLama:

1. Campaign Audit.
2. UTM Generator.
3. Autopolicies Sandbox.
4. Bid/Budget Simulator.
5. Monitoring Alerts.

Это усиливает demo без необходимости реального Direct API.

---

## Обновлённый MVP-фокус

DirectPilot Beta теперь лучше формулировать так:

> API-first demo/autopilot для малого бизнеса в Яндекс Директе: показывает ошибки кампаний, генерирует UTM, симулирует автоправила и бюджетные сценарии, объясняет рекомендации и применяет изменения только после approve.

---

## Риски / неопределённость

- Публичные страницы eLama — маркетинговые; без доступа к кабинету нельзя проверить реальный UX.
- Тарифы и условия eLama могут меняться.
- Автоправила и бид-менеджмент в live требуют строгих budget guardrails.
- Нельзя обещать гарантированные заявки/прибыль.
- Для малого бизнеса мало данных, поэтому рекомендации должны иметь confidence и пороги минимальной статистики.
